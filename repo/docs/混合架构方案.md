# 拼豆工坊 · 混合架构部署方案（服务器 + PHP 代理 + GitHub 数据）

> 状态：已落地（代码在 `repo/` 下，GitHub 仅作数据库）
> 决策：管理后台 → 服务器 PHP 代理（PAT 存服务器，不出浏览器）；GitHub 仅作数据库；小程序 → 独立最小权限 PAT 直连 GitHub（`repo/data/**` 仅读写）。

---

## 1. 目标与动机

此前为"零运维、绕开备案"采用了纯 GitHub 方案，代价是 **Fine-grained PAT 被写进浏览器 `localStorage`（管理后台）和小程序包 `app.js`（用户端）**。任何人 F12 看一眼或反编译小程序都能拿到有仓库写权限的令牌——这是当时方案最大的安全隐患。

本方案把"鉴权与交互"收口到我们自己的服务器：

- **PAT 永不出浏览器**：只躺在服务器 `config.php`（放在 web 根之外、`chmod 600`、并 gitignore）。
- **PHP 能做"校验"**：服务端校验参数、限流、可加 Admin Key，这是纯前端做不到的额外红利。
- **GitHub 退化为纯存储**：页面交互与鉴权全收口到自有服务器。

---

## 2. 架构总览

```
[ 管理后台网页 ]  --同源 AJAX-->  [ 服务器 PHP 代理 ]  ==HTTPS==>  [ GitHub 仓库 ]
 (服务器托管)                    (持有 PAT-A，做校验)                (repo/data/*.json 仅作 DB)
                                      ^
[ 微信小程序 ]  --直连(最小权限PAT-B)--┘ 或 走服务器(需备案)
```

- 管理后台这条线：**彻底无客户端令牌**，最安全。
- 小程序这条线：受微信"request 域名须已备案 HTTPS"约束，未备案时只能直连 GitHub；因此给它一把**独立、仅限 `repo/data/**` 读写**的 PAT-B，即便被反编译抠出也动不了 `stations`/`settings`。备案完成后可改走服务器代理，做到全链路无客户端令牌。

---

## 3. 安全模型与威胁分析

### 3.1 当前纯 GitHub 方案的风险
| 风险点 | 说明 |
|---|---|
| 管理后台 PAT 在 `localStorage` | 打开页面 F12 即可提取，有仓库写权限 |
| 小程序 PAT 在 `app.js` | 小程序包可被反编译提取 |
| 无服务端校验 | 任何拿到令牌的人可随意读写、注入脏数据 |

### 3.2 本方案的缓解点
- PAT-A 只在服务器，浏览器/小程序包里**完全没有**管理用令牌。
- PAT-B 仅授权 `repo/data/**`，爆破半径被锁死在会话数据。
- 服务端统一校验入参（字段、类型、范围、station 存在性），脏写被挡在 GitHub 之前。
- 可选 Admin Key：即使有人猜到 `/api` 地址，无密钥也写不进。
- 服务器是无状态代理（不落本地库），需保护面更小。

### 3.3 残留风险（诚实列出）
- **服务器成为新"皇冠明珠"**：服务器被攻破 → PAT-A 泄露。缓解：配置文件权限收紧、服务器只跑这一件事、最小镜像。
- **PAT-B 仍内嵌小程序**（未备案前不可避免），靠最小权限兜底。
- **并发写冲突**：GitHub Contents 无事务，两人同时改可能互相覆盖。用 `sha` 乐观锁 + 重试兜底（见 5.2）。店铺低并发场景可接受。
- **Admin 走服务器 IP**：浏览器不强制备案可用，但生产建议仍配备案域名 + HTTPS 证书。

---

## 4. 令牌规划（两个 Fine-grained PAT）

| 名称 | 用途 | GitHub 授权范围 | 存放位置 |
|---|---|---|---|
| **PAT-A** | 服务器 PHP 代理 | 仓库 Contents：**Read/Write**（覆盖 `repo/data/**` 及 `repo/admin/beep.wav` 等） | 服务器 `/etc/bean/config.php`，`chmod 600` |
| **PAT-B** | 小程序直连 | 仓库 Contents：**Read/Write**，但 **Path 限制为 `repo/data/**`** | 小程序 `app.js` 的 `githubToken`（仅此一处的令牌） |

> 两张令牌**独立生成、独立吊销**。任一张泄露，另一张与 `stations`/`settings` 配置不受影响。

---

## 5. 服务器端设计

### 5.1 目录结构（部署在服务器 web 根下）
```
/var/www/bean/                 # web 根（nginx/apache 指向此），内容来自仓库 repo/ 目录
├── admin/
│   └── index.html             # 管理后台：改为调用同域 /api/*.php
└── api/
    ├── bootstrap.php          # 公共：加载 config、GitHub 客户端封装、校验函数
    ├── stations.php           # GET / PUT  stations（GitHub 路径 repo/data/stations.json）
    ├── sessions.php           # GET / POST / PUT  sessions（repo/data/sessions.json）
    ├── settings.php           # GET / PUT  settings（repo/data/settings.json）
    └── qr.php                 # 桌号二维码生成/读取

/etc/bean/config.php           # 真实配置（web 根之外，gitignore，chmod 600）
```

### 5.2 `bootstrap.php` 核心封装（示意）
```php
<?php
// 仅服务端可见：从 web 根外读取真实配置
$CFG = require '/etc/bean/config.php';
define('GH_API', 'https://api.github.com/repos/'.$CFG['owner'].'/'.$CFG['repo'].'/contents/');
$headers = [
  'Authorization: Bearer '.$CFG['pat_a'],
  'Accept: application/vnd.github+json',
  'User-Agent: bean-admin',
  'X-GitHub-Api-Version: 2022-11-28',
];

// 读取文件内容（返回解码后的 PHP 数组）
function gh_read(string $path): array {
  global $headers;
  $ch = curl_init(GH_API.$path);
  curl_setopt_array($ch, [CURLOPT_HTTPHEADER=>$headers, CURLOPT_RETURNTRANSFER=>true]);
  $raw = json_decode(curl_exec($ch), true);
  return ['sha'=>@$raw['sha'], 'data'=>json_decode(base64_decode(@$raw['content']), true)];
}

// 乐观锁写回（带 sha，冲突自动重试一次）
function gh_write(string $path, array $data, string $msg): bool {
  global $headers;
  $cur = gh_read($path);
  $body = json_encode([
    'message'=>$msg, 'branch'=>'main',
    'content'=>base64_encode(json_encode($data, JSON_UNESCAPED_UNICODE|JSON_PRETTY_PRINT)),
    'sha'=>$cur['sha'],
  ]);
  $ch = curl_init(GH_API.$path);
  curl_setopt_array($ch, [CURLOPT_HTTPHEADER=>$headers, CURLOPT_RETURNTRANSFER=>true,
    CURLOPT_CUSTOMREQUEST=>'PUT', CURLOPT_POSTFIELDS=>$body]);
  $resp = curl_exec($ch);
  $code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
  if ($code === 409) { // 并发冲突，重读后重试一次
    $cur = gh_read($path);
    $body = json_encode([...json_decode($body,true), 'sha'=>$cur['sha']]);
    curl_setopt($ch, CURLOPT_POSTFIELDS, $body);
    $resp = curl_exec($ch); $code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
  }
  return $code === 200 || $code === 201;
}

// 可选 Admin Key 闸门
function require_admin_key(): void {
  global $CFG;
  if (($CFG['admin_key'] ?? '') === '') return; // 未启用则跳过
  if (($_SERVER['HTTP_X_ADMIN_KEY'] ?? '') !== $CFG['admin_key']) {
    http_response_code(403); exit('forbidden');
  }
}
```

### 5.3 端点清单
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/stations.php` | 读取全部台位 |
| PUT | `/api/stations.php` | 新增/编辑台位 |
| GET | `/api/sessions.php?status=active` | 读取使用中/历史会话 |
| POST | `/api/sessions.php` | 新建会话（用户扫码落座） |
| PUT | `/api/sessions.php` | 更新会话（强制结束 / 续时）。续时仅由管理后台发起，用户端不提供自助延长 |
| GET | `/api/settings.php` | 读取店铺设置 |
| PUT | `/api/settings.php` | 更新设置 |
| GET | `/api/qr.php?station=3` | 返回该桌号二维码图片 |

### 5.4 服务端校验规则（"校验"的核心）
- 仅接受 `application/json`，非法直接 400。
- 必填字段存在性 & 类型校验（如 `station_id` 为整数、`planned_minutes` 1–600、`nickname` 长度 ≤ 20）。
- 写会话前校验 `station_id` 存在于 `stations.json`。
- 简单限流：每 IP 每端点按时间窗口限频（可用文件/APCu 计数器），防脚本刷接口。
- 写操作统一走 `require_admin_key()`（若启用 Admin Key）。

## 6. 管理后台改造（admin/index.html）
- **移除**：localStorage 里的 owner/repo/token 输入与读取逻辑。
- **改为**：所有 CRUD 调用同域 `/api/*.php`（同源，无需 CORS，令牌不进浏览器）。
- **配置**：owner/repo 等仍由服务器 `config.php` 提供，前端不再持有任何密钥。
- 若启用 Admin Key：首次打开弹窗让店主输入一次，存内存，后续请求带 `X-Admin-Key` 头。

---

## 7. 小程序改造（miniapp）
- `app.js`：保留 `githubOwner` / `githubRepo`，将 `githubToken` **替换为 PAT-B（仅 `repo/data/**`）**。
- `utils/api.js`：`readData`/`writeData` 逻辑不变（read/write 均指向 GitHub 路径 `repo/data/`），令牌源改为 PAT-B。
- 微信后台：**`api.github.com` 加入 request 合法域名**（与现状一致，未变）。
- 提示音 `beep.wav`：继续用 jsDelivr CDN（`https://cdn.jsdelivr.net/gh/{owner}/{repo}@main/repo/admin/beep.wav`），无需令牌、无需改。
- 备案完成后（可选）：把 `utils/api.js` 的基地址从 `api.github.com` 切到服务器 `/api`，即可彻底移除客户端令牌。

## 8. 部署步骤
1. 服务器装 PHP 8.x + Web 服务器（小店规模可用 nginx+php-fpm；极简可用 `php -S`，仅测试）。
2. 将仓库 `repo/` 下的 `admin/`、`api/` 放到 web 根；`config.php` 放 `/etc/bean/`（web 根外）。
3. 填 `config.php`：`owner`、`repo`、`branch=main`、`pat_a`、`admin_key`(可选)。
4. `chmod 600 /etc/bean/config.php && chown www-data:www-data /etc/bean/config.php`。
5. GitHub 生成 **PAT-A**（Contents RW 全仓库）与 **PAT-B**（Contents RW，Path 限 `repo/data/**`）。
6. 确认 `repo/data/*.json` 已 push 到仓库 `main`（现状已具备）。
7. 自测：打开管理后台 URL → 增删台位 → 小程序扫码落座 → 结束计时。
8. 小程序：填 PAT-B 到 `app.js`、`api.github.com` 加白、重新构建上传。

## 9. 从现状迁移
- **数据零迁移**：GitHub 上 `repo/data/*.json` 结构不变，直接复用。
- **代码变更**：新增服务器 `api/`（位于 `repo/`） + `config.php`；`admin/index.html` 改调同域接口；小程序 `app.js` 令牌换 PAT-B。
- **空 `server/` 目录**：之前遗留的空目录可删除（不影响任何东西），PHP 实际落在 web 根而非此处。
